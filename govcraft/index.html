The problem

A oneGov service is assembled through the platform's own interface: a workflow canvas, form builders, database tables, document templates, task definitions and payment steps. Building one means hundreds of clicks across all of those, and every piece references the others by id.

A single stale reference or an unreachable branch does not announce itself. It surfaces later, when a citizen's application is already stuck in production and somebody has to trace it by hand. There was no way to check a service before activating it, and no reliable way to repeat a build across environments.

What I built

A typed server that exposes the platform's API as 162 callable operations, so a whole service can be created and configured from code instead of by hand. Workflows, forms, DataHub schemas, document templates, tasks and payments are all reachable programmatically.

On top of that sit around 30 versioned playbooks encoding the team's standard operating procedures: how to build a workflow, how to clone one safely into a new version, how to design a form, how to migrate a document template between formats. Those procedures used to live in people's heads and in documents nobody opened. Now they are executable.

The part that mattered

Two quality gates the team did not previously have.

Pre-flight linting

A deterministic pass that reads an entire service and reports what is broken before anyone activates it: references pointing at nodes that no longer exist, graph deadlocks where an application can reach a state it can never leave, and triggers wired to events that never fire.

Unattended smoke runs

The server submits a real application through a service in the training environment and follows it to completion. The flow is proven to work before go-live rather than after, which is the difference between finding a defect in testing and finding it in a citizen's case file.

Sharp edges, now encoded

The platform has failure modes that took real debugging to find. Each one is a guard in the server rather than something the next person has to rediscover.

  • Expressions are substituted before they are parsed. A reference nested inside a string literal produces a parse error at runtime, so the instance fails rather than the expression simply evaluating to nothing.
  • A form field bound to a variable of the wrong type kills the handshake. No instance is created at all, which means there is nothing in any list to find and nothing to restart. It is invisible unless you know to look.
  • Services built through the API without an output specification can never be duplicated. The copy fails permanently, long after the service was created. The server now sets it on the way in.

Where it stands

Around 12,000 lines of TypeScript with its own CI, release automation and test suite. It is used across the solutions team to build, migrate and quality-gate oneGov services, and it replaced manual configuration as the way that work gets done.
